# ЛР 5. Skip Happens: деревья решений

## Задача

Вы работаете в музыкальном сервисе. Пользователи хотят слушать музыку,
а не постоянно нажимать «следующий трек». Команда предлагает заранее
находить неудачные рекомендации с помощью дерева решений.

Вам даны характеристики трека, история предпочтений пользователя
и контекст прослушивания. Одна строка — одно событие: пользователь
получил следующий трек. Целевая переменная `skip` показывает его реакцию:

```text
0 = пользователь продолжил слушать
1 = пользователь пропустил трек
```

На этих данных нужно подготовить решения для трёх сценариев.
У них одна целевая переменная, но разные требования к прогнозу.

### 1. Аккуратная корректировка очереди — careful

Сервис проверяет уже собранную очередь и может заменить трек другой
рекомендацией. Замена трека, который пользователь стал бы слушать,
нарушает его выбор и считается более серьёзной ошибкой, чем оставленный
в очереди трек, который он затем пропустит.

Нужно находить неудачные рекомендации, избегая лишних замен хороших треков.
При настройке можно пожертвовать частью найденных пропусков ради более
осторожного решения. При этом оставленные будущие пропуски тоже являются
ошибками: решение «оставить всё» нужно сравнить с вашей моделью.

Ответ модели: **0 — оставить трек, 1 — заменить**.
Выберите показатель, который учитывает оба типа ошибок и отражает
разницу в их последствиях.

### 2. Очередь без постоянных пропусков — rescue

В режиме непрерывного прослушивания сервис пытается заранее убрать треки,
на которых пользователю придётся нажать «следующий». Здесь важнее
обнаружить как можно больше будущих пропусков, чем в первом сценарии.

Оставленный неудачный трек — основная проблема. Но замена хорошего трека
тоже ухудшает рекомендации, поэтому решение «заменить всё» не является
целью. Требуется найти баланс с приоритетом обнаружения будущих пропусков.

Ответ модели: **0 — оставить трек, 1 — заменить**.
Выберите показатель, который учитывает и найденные пропуски,
и неоправданные замены, с учётом приоритета этого сценария.

В обоих сценариях есть два типа ошибок:

| Реакция пользователя | Решение модели | Что произошло |
|---|---|---|
| Продолжил бы слушать (`skip = 0`) | Заменить (`1`) | Убрали хороший трек — FP |
| Пропустил бы (`skip = 1`) | Оставить (`0`) | Не обнаружили будущий пропуск — FN |

Положительный класс во всех метриках — **пропуск, `skip = 1`**.
Классификацию получайте из вероятности: заменить трек, если
`probability >= threshold`. Порог выбирайте по локальной валидации;
он может различаться между сценариями.

### 3. Вероятность пропуска для следующего компонента — probability

Компонент, который собирает очередь, использует вероятность пропуска
для сравнения риска разных рекомендаций. Ему нужно различать почти
неизбежный пропуск, сомнительный вариант и трек, который скорее понравится.

Ответ модели: **число от 0 до 1 — вероятность `skip = 1`**.
Например, прогноз 0.8 означает, что среди многих похожих событий
с такой оценкой ожидается примерно 80% пропусков.

Оценивайте сами вероятности. Уверенная ошибка, например прогноз 0.99
для трека, который пользователь продолжил слушать, должна ухудшать качество
сильнее, чем менее уверенный прогноз 0.6 при том же ответе.
Выберите показатель для вероятностного прогноза. Порог для итогового
ответа этого сценария не используется.

Для каждого сценария самостоятельно выберите показатели качества,
обоснуйте их через требования выше и подберите признаки и параметры дерева.
Конкретные показатели скрытой оценки и их параметры до дедлайна не раскрываются.

## Данные

В `data/train.csv` содержится **5 000 объектов**, 40 признаков
и целевая переменная `skip`. Данные синтетические: это учебная симуляция
музыкального сервиса. Описание колонок — в `data/README.md`.
Все признаки записаны числами; среди них есть числовые величины,
бинарные признаки и коды категорий.

Готовой валидационной выборки нет. Вы самостоятельно выбираете разбиение
или cross-validation. При настройке обучайте дерево и всю
предобработку, требующую обучения, только на обучающей части. Оценивайте
качество на объектах, не использованных для обучения этой модели.
Для выбора признаков, параметров и порогов используйте локальную валидацию.

После выбора конфигурации финальное дерево обучается на всех выданных данных.

Во время работы решение проверяется на скрытой выборке из **3 000 объектов**.
Финальная оценка выставляется на другой скрытой выборке из **6 000 объектов**.
Признаки и ответы обеих выборок не выдаются.

## Обязательная реализация

В этой работе недостаточно вызвать готовое дерево из библиотеки.

В `model.py` самостоятельно реализуйте бинарное дерево классификации:

- критерий Gini и поиск лучшего разбиения;
- построение дерева с ограничениями `max_depth` и `min_samples_leaf`;
- предсказание вероятности и класса;
- сохранение и загрузку обученного состояния.

`max_depth` — неотрицательное целое число или `None`; 0 означает один лист.
`min_samples_leaf` — положительное целое число. Эти параметры ограничивают
глубину дерева и минимальное
число обучающих объектов в каждом листе. Разбиение не должно создавать
листья меньшего размера. Для глубины без ограничения используйте `None`
в Python и `null` в JSON.

Вероятность класса 1 в листе рассчитывайте как
`(n_1 + smoothing) / (n + 2 * smoothing)`, где `n` — число обучающих объектов
в листе, `n_1` — число пропусков среди них, `smoothing >= 0`.
При нулевом сглаживании получается обычная доля класса 1.
Сглаживание выбирайте по локальной валидации.

В `metrics.py` самостоятельно реализуйте метрики качества:

| Функция | Что измеряет |
|---|---|
| `precision` | Долю настоящих пропусков среди предсказанных пропусков |
| `recall` | Долю обнаруженных пропусков среди всех настоящих пропусков |
| `fbeta` | Совместную оценку precision и recall; `beta` задаёт их относительный приоритет |
| `error_cost` | Среднюю стоимость FP и FN с выбранными весами |
| `binary_log_loss` | Качество вероятностей с учётом уверенности в ответе |

Сигнатуры, формулы и правила крайних случаев указаны в файле.
Эти функции не назначены заранее конкретным сценариям: выбор показателей
и их параметры выбирайте самостоятельно.
Для первых двух сценариев сравнивайте решения 0/1, для третьего
основной показатель должен оценивать вероятности.

В `selection.py` реализуйте permutation importance и отбор признаков.
Importance измеряет, насколько ухудшается выбранный показатель после
перестановки значений одной колонки. Оценивайте её на локальной валидации,
повторив перестановку каждой колонки минимум три раза. Модель при этом
не переобучается; порог и параметры показателя остаются фиксированными.

## Выбор признаков

Можно создавать признаки из выданных колонок. Исследуйте взаимодействия:
например, как характеристика трека работает в разных контекстах или как
жанр текущего трека связан с составом истории плейлиста. Сравните дерево
на исходных колонках с деревом, использующим такие признаки.

Число признаков в финальной модели не ограничено. Самостоятельно решите,
какие признаки оставить для каждого сценария, по результатам локальной валидации.
Сравните полный набор с сокращёнными наборами разного размера.
Если сокращение ухудшает результат, можно оставить все признаки.

В конфигурации объявите используемые **исходные колонки**.
Проверяющий передаёт модели только их. Например, если новый признак
вычисляется из жанра трека и состава плейлиста, объявите все колонки,
необходимые для его расчёта. Создание производных признаков должно
выполняться внутри вашего решения и одинаково работать при fit и predict.

## Что разрешено

- NumPy и pandas для вычислений и обработки данных.
- Создание и отбор признаков, настройка дерева, порога и сглаживания.
- Собственные дополнительные Python-модули.
- Готовые модели и метрики для локального сравнения, вне сдаваемой реализации.

**В каждом сценарии прогноз должно выдавать ровно одно самостоятельно
реализованное дерево.** Можно использовать разные конфигурации или
одинаковые деревья с разными порогами. Три различные структуры не требуются.

Запрещены random forest, bagging, boosting, stacking, voting,
усреднение нескольких деревьев и отдельные деревья для сегментов пользователей.
Нельзя заменить дерево другой моделью или использовать дополнительную
предсказывающую модель в предобработке. Готовые реализации дерева
и метрик нельзя использовать вместо обязательной собственной реализации.

Cross-validation разрешена для настройки. Финальное решение не должно
усреднять прогнозы моделей, обученных на разных folds.

## Шаблон решения

В `model.py` реализуйте класс `Model` с интерфейсом:

- `fit(X, y)` — обучение дерева и предобработки; возвращает `self`.
- `predict_proba(X)` — одномерный массив вероятностей класса 1.
- `predict(X)` — классы 0 или 1 по выбранному порогу.
- `save(path)` — сохранение всего обученного состояния в один файл.
- `Model.load(path)` — загрузка модели из этого файла.

`X` — `pandas.DataFrame` с объявленными исходными колонками,
`y` — `pandas.Series` с целевой переменной. Предсказания сохраняют
порядок входных строк. Вероятности — конечные числа от 0 до 1;
правило получения класса: `probability >= threshold`.

В `submission.json` задайте конфигурации `careful`, `rescue`, `probability`:
`features`, `max_depth`, `min_samples_leaf`, `threshold`, `smoothing`.
Структура показана в `submission.example.json`. Это пример формата,
а не рекомендованные признаки и параметры.
Для `probability` оставьте `threshold = 0.5`: в этом сценарии
проверяющий использует `predict_proba`, а не ответ после применения порога.
Для `careful` и `rescue` используется `predict`.

Проверяющая программа создаёт отдельный `Model(case=..., **config)`
для каждого сценария и вызывает `fit` на всех 5 000 выданных объектах.
Конфигурации выбирайте по локальной валидации.
Заранее обученную модель сдавать не нужно.

Решение должно быть детерминированным. Зафиксируйте seed, если используете
случайность. Сохранение и загрузка должны сохранять прогнозы.

## Оценивание

Итоговая оценка — от 0 до **100 баллов**:

```text
Итог = (50 × Q + 25 × T + 25 × M) × H
```

- `Q` — среднее качество трёх сценариев после перевода их скрытых показателей
  в шкалу от 0 до 1. Сценарии имеют одинаковый вес. Шкалы фиксируются
  до выдачи задания; качество константного решения служит нулевым ориентиром.
- `T` — оценка времени: среднее оценок обучения и инференса трёх моделей.
- `M` — оценка суммарного размера трёх сохранённых моделей в байтах.
- `H` — доля пройденных скрытых технических проверок: число пройденных
  проверок, делённое на их общее число. Это множитель всей оценки.

Например, при 80 баллах до множителя и 75% пройденных скрытых проверок
итог составляет 60 баллов. Открытые тесты служат для разработки и не входят
в `H`.

Для каждого ресурсного показателя применяется одна формула:

```text
R(x) = min(1, 0.7 × x_reference / x)
T = (R(fit_seconds) + R(predict_seconds)) / 2
M = R(model_size_bytes)
```

Базовый преподавательский CART получает 70% по каждому ресурсному показателю.
Меньшее время и меньший файл дают больше баллов, максимальная доля — 1.
Численные ориентиры опубликованы в `resource_reference.json`.

Обучение и инференс запускаются в разных процессах. Для каждого замера
обучаются три модели на всех 5 000 строках и суммируется время вызовов `fit`.
При инференсе модели загружаются с диска, затем измеряется суммарное время
`predict` для `careful`/`rescue` и `predict_proba` для `probability`
на скрытой выборке. Время загрузки CSV, импортов, сохранения и загрузки модели
в этот замер не входит. Инференс выполняется после одного прогрева
на 32 строках. Каждый этап повторяется три раза; используется медиана времени.
При различии размеров сохранённых файлов учитывается наибольшая сумма.
Повторное обучение и загрузка должны давать одинаковые ответы.

Окружение фиксировано: один CPU, один поток вычислений, лимит RAM 1 ГиБ.
RAM является техническим ограничением; в `M` учитывается размер файлов моделей.
Каждый этап должен завершиться за 180 секунд. Суммарный размер сохранённых
моделей — не более 200 МБ. Зависимости решения из сети не устанавливаются:
используйте NumPy, pandas и стандартную библиотеку Python.

Если решение не обучается, не сохраняется, превышает лимиты или возвращает
ответы неверного формата, за попытку выставляется 0. Сбой инфраструктуры
не оценивается и не расходует попытку.

Названия показателей качества по сценариям, их параметры и точные шкалы
до дедлайна не раскрываются. Ваш выбор показателей для локальной валидации
не меняет правило оценки бота. Выбирайте показатель с учётом последствий ошибок.
